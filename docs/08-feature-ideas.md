# 機能アイデア集(楽しさ向上)

2026-07-24 のブレインストーミング結果。実装済み機能(素材ライブラリ・公開ギャラリー・ユーザーページ・小説化・成長ポイント)を土台に、「付け加えると楽しくなる」候補を楽しさ/手間の比率で整理したもの。各案は未着手であり、着手時は個別に設計(ブレインストーミング→spec)を行うこと。

関連: [05-ui-ux.md](05-ui-ux.md)(キャラシートパネル・テンション制御の未実装記述)、[07-risks-and-roadmap.md](07-risks-and-roadmap.md)(Phase 3・10.1節ルールセットアダプタ実装済み)。

## 1. おすすめ度の高い案(楽しさ/手間の比率が良い)

### 1.1 場面挿絵の生成(初期案の復活。Phase 3「画像生成連携」に対応)

**サブプロジェクト1 実装済み(2026-07-24)**: 画像生成基盤(Gemini)+ Playシーン挿絵(手動/自動トグル)+ 見た目レジストリによるキャラの一貫性(テキスト方式)。
**サブプロジェクト2 実装済み(2026-07-24)**: 挿絵付き小説化(マーカー方式でbase64画像埋め込みMarkdownをダウンロード)。
**サブプロジェクト3 実装済み(2026-07-24)**: 初登場キャラの自動ポートレート生成+参照画像(最大3枚)によるシーン一貫性の強化。
**1.1は全サブプロジェクト完了。** 詳細は [06-content-generation.md](06-content-generation.md) 10.5節。


- シーン切り替わりやクライマックスで挿絵を1枚生成し、GMの地の文の上に表示する。
- コスト・待ち時間対策として「新シーン突入時だけ自動」+「この場面を描く」ボタンでの手動生成の2本立てが現実的。
- 生成画像をセッションに紐づけて保存すれば、既存の小説化機能と合体して**挿絵付き小説**としてダウンロード可能になり、公開ギャラリーの小説タブの見栄えも向上する。
- キャラクターのポートレート生成(ライブラリのCharacterタブに顔絵)も同じ仕組みの流用で実現できる。
- 注意: 画像生成はAnthropic APIでは提供されないため、別プロバイダのAPIをプロキシサーバー経由で追加する必要がある。

### 1.2 Play画面の「演出」強化 ★最有力 — **実装済み(2026-07-24)**

13章(テンション制御)のプロンプト側構想をUIまで貫通させる。外部API不要・既存データを活かせて、プレイの一番美味しい瞬間を直接楽しくする。

- **ダイスロール演出**: d100が転がるアニメーション→成功/失敗/クリティカル/ファンブルで色とエフェクトが変わる。「ダイスを振る瞬間の緊張」はTRPGで最も楽しい部分であり費用対効果が高い。
- **タイプライター表示**: GMの地の文を一文字ずつ流す。`tension_level`で速度を変える(緊迫場面は速く短く、平穏場面はゆったり)と13.1節の文体指示と噛み合う。
- **雰囲気連動テーマ**: World/Scenarioの`moods`(固定8種)に応じてプレイ中の背景色・装飾を変える(ホラーなら暗く、ほのぼのなら暖色など)。既存データを使うだけなので安上がり。

### 1.3 キャラシート常設パネル — **実装済み(2026-07-24)**

Play画面に`CharacterPanel`を追加。広い画面は右端常設、狭い画面はヘッダー「PC」トグルのドロワーで、PCシート本文・目標/因縁・成長ポイントを読み取り表示する。入手情報は生フラグ一覧ではなく「これまでを思い出す」ボタンによるPC視点のオンデマンド回想(`recallMemory`)に変更(2026-07-24、生フラグの英語キー羅列は見づらく没入も削ぐため非開示)。詳細は [05-ui-ux.md](05-ui-ux.md) 7章。

- 05-ui-ux.md 7章に「未実装」と明記。現状はPC情報を見るのにライブラリへ戻る必要がある。
- Play画面のサイドパネル(モバイルでは開閉式)にPCシート+成長ポイント+入手情報を常時表示する。
- 地味だが「自分のキャラを操作している」感覚を底上げする効果が大きい。

## 2. 中期的に面白そうな案

- **エンディングコレクション/実績**: **実装済み(2026-07-25)**。セッション完結(`endedAt`)を確定すると、GMがエンディングタイトル・総括を1回のAI呼び出しで命名し(`server/endingNaming.js`、06-content-generation.md 10.7節)、`users/{userId}/endings/{sessionId}`に完結時点のスナップショットとして記録する(02-data-model.md 3.6節)。ダイス統計(`src/engine/rollStats.js`)はルールセットの判定式アダプタが持つ`degrees`語彙をそのまま出し分ける方式で実装しており、ハード成功/イクストリーム成功と正気度はCoC7e風の記録にだけ現れる。実績(`src/engine/achievements.js`)は8種の固定カタログで、エンディング記録のコレクションから都度導出する(保存を持たず、未獲得もグレーで表示)。図鑑画面はハッシュルート`#/endings`(`src/screens/EndingGallery.jsx`、05-ui-ux.md 14.6節)で、ホームのボタン行から遷移し記録の改名・削除もそこで行う。**非対象のまま残る**: エンディングの公開/ギャラリー連携(既存の公開基盤に乗せられるが本機能のスコープには含めない。下記「公開シナリオの『遊ばれた数』とリアクション」ともスコープを混ぜない)、ユーザー定義の実績、エンディング分岐ツリーの可視化、完結後にセッションを続けた場合の記録の自動更新(記録し直しは手動)。設計は[superpowers/specs/2026-07-25-ending-collection-design.md](superpowers/specs/2026-07-25-ending-collection-design.md)。
- **公開シナリオの「遊ばれた数」とリアクション**: 公開・インポート基盤の上に「遊んだ人数」「絵文字リアクション」を追加。素材を公開する楽しみが生まれ、ユーザーページの充実にもつながる。
- **キャンペーン(連作シナリオ)**: **SP1(コアループ)実装済み(2026-07-24、02-data-model.md 3.5節)**。オープンな連鎖+テキスト方式の引き継ぎ(`advanceCampaignPc`がPCシートを更新、xpは数値で持ち越す)で「育てたキャラで次の冒険へ」を実現。ライブラリWorld由来セッションのホームカードに「次の章へ」ボタン。**SP2(管理タブ+Homeグルーピング)実装済み(2026-07-25)**:素材ライブラリのCampaignタブで一覧・章閲覧・改名・削除、ホームで`campaignId`付きセッションをキャンペーン単位にグループ表示。**章からの再開・クロスWorld・構造化インベントリ・NPC記憶連携・次章シナリオ自動提案はSP3以降**。NPC記憶モデル(Phase 3)とセットで効く。
- **ルールセット判定アダプタ**: **実装済み(2026-07-25)**。判定式(simple/coc7e/dnd5e/gurps)を`src/engine/rulesetAdapters.js`でアダプタ化し、CoC7e風はハード/イクストリーム成功とSAN(正気度、初期60/上限99、`check_kind='sanity'`でAI駆動発火・決定論的減少)を実装。カスタムRulesetも基準式を選択可能。HP等の追加リソース・シナリオ側イベントタグ方式の副作用トリガーは非対象(07-risks-and-roadmap.md 10.1節)。

## 3. 大物(効果は大きいが覚悟が要る)

- **マルチプレイヤー**(Phase 3): 同期・ターン管理の作り込みが必要で、無認証プロキシ問題(07-risks-and-roadmap.md 12章)の解決が前提。
- **音声**: GMナレーション読み上げ(TTS)、雰囲気連動のアンビエントBGM。没入感は高いがコストとアセット管理が増える。

## 4. 推奨着手順

1. **Play画面の演出強化(1.2、特にダイスロール演出)** — 外部API不要、既存データ(moods/tension)を活用、効果が即体感できる。
2. **場面挿絵生成+挿絵付き小説化(1.1)** — 公開ギャラリーという既存の強みと相乗効果。
3. **キャラシート常設パネル(1.3)** — ドキュメント上も既知のギャップで、体験の底上げ。
