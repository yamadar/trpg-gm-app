# デザインクリティーク: GM's Desk

実施日: 2026-07-26 / 対象: Home・公開ギャラリー(デスクトップ 1280×720 / モバイル 375×812)
方法: 実際に dev サーバを起動し、描画結果・計算済みスタイル・フォーカス順序を実測

> **検証範囲の限定**: **Setup ウィザードと Play 画面(本体験の中核)は実画面を確認していない**。Play の開始は API 消費とデータ生成を伴うため、確認を取らずに実行しなかった。この 2 画面についてはコード読解に基づく指摘に留めている。
>
> **Home は未ログイン状態と、ログイン状態の両方を確認した。両者は別物であり、下記では区別して記述している。**

## 全体の印象

**「セピアの紙とタイプライター」という世界観の設計は成功している。** `Special Elite` の見出し、`Source Serif 4` の本文、紙色 `#EDE6D6` の組み合わせは狙いどおりに機能しており、TRPG のリプレイ集を思わせる質感がある。ここは守るべき資産である。

最大の機会は **「見た目の階層」と「実際に操作できるもの」が一致していないこと**。装飾的な完成度に対し、操作の設計が追いついていない。象徴的なのは公開ギャラリーで、**キーボードでフィルタと検索は使えるのに、一覧のどの作品も開けない**。見えているものと触れるものがずれている。

## ユーザビリティ

| 所見 | 深刻度 | 推奨対応 |
|------|--------|----------|
| **公開ギャラリーの作品を1つも開けない(キーボード)** — Tab 到達可能 18 要素の内訳は ログイン/閉じる/検索/雰囲気フィルタ8/「公式サンプル」×7。**作品カード 7 件はいずれもフォーカス不能**。一方でカードは `cursor: pointer` で `<div>` のまま | 🔴 Critical | カードを `<button>` 化し、アクセシブル名を作品名にする |
| **Tab 順に「公式サンプル」が7個連続する** — すべて同一ラベルで、どれがどの作品の作者リンクか区別できない | 🔴 Critical | 「〈作品名〉の作者 公式サンプル」等、文脈を含む名前にする |
| **フォーカスされても見た目が一切変わらない** — 検索欄にフォーカスした状態で `outline-style: none` / `box-shadow: none` / 枠線色も未変更。実測で非フォーカス時と完全に同一 | 🔴 Critical | `theme.js` の `inputStyle` から `outline: 'none'` を撤廃し `:focus-visible` リングを定義 |

| **モバイルで「ログイン」が「閉じる」に重なる** — 375px 幅で 73×4px 重複。`elementFromPoint` で閉じるボタン上端はログインボタンに occlude されている | 🟡 Moderate | 画面ヘッダを固定 AuthBar と同一行に収める、または `閉じる` に上マージンを確保 |
| **「追加にはログインが必要です(右上からログイン)」が7回反復** — 「おすすめ」タブでカードごとに出る。スクリーンリーダーでは同じ文を7回聞くことになる | 🟡 Moderate | ページ先頭に1回だけ表示する |
| **`Button` に `type` 指定が無い** — 全ボタンが既定の `type="submit"`。`<form>` 内に置いた瞬間に意図しない送信が起きる | 🟡 Moderate | `Button.jsx` に `type="button"` を既定として付与 |
| **検索欄が placeholder をラベル代わりにしている** — 入力開始と同時に「何を検索する欄か」が消える(`aria-label` はあるので AT は可) | 🟢 Minor | 可視ラベルを付ける、または入力後も残る補助文を添える |
| **「公式サンプル」ボタンの高さが 18px** — 実測 18px。誤タップしやすい | 🟢 Minor | 24×24 以上を確保 |

## ビジュアルヒエラルキー

### 最初に目が行くもの
**Home(未ログイン)**: brass 塗りの「+ 新規プレイ」。**これは誤り** — 押せないボタン(`disabled`)が最も強い視覚的重みを持っている。本来ここで最初に目が行くべきは、実際に必要な最初の行動である「ログイン」だが、それは右上隅の小さなボタンに追いやられている。**階層が反転している。**

**Home(ログイン後)**: 「はじめての冒険を選ぶ」見出しとスターター一覧。**これは正しい。** 各カードに導入文と「この冒険を始める」CTA が揃っており、未ログイン時とは別物の完成度がある。

### 視線の流れ

**Home(未ログイン / デスクトップ 1280px)**: コンテンツが左上の約 25% に固まり、**画面の 3/4 が空の紙**。アプリの中身を何ひとつ見せないまま、主要 CTA は押せない。**初回訪問者だけが、最も貧しい版の Home を見ることになる。**

**Home(ログイン後)**: 内容は良いが、**主要ナビゲーション(新規プレイ / 素材ライブラリ / 公開ギャラリー / エンディング図鑑)がスターターカード8枚の下、ページ最下部にある**。ライブラリやギャラリーへ行くたびに長いスクロールが要る。初回は「まず1つ選ぶ」導線として正しくても、2回目以降の利用者にとっては毎回の摩擦になる。

**AuthBar が本文に重なる**: 固定配置のユーザー名「syatin」がスクロール中にカード右上のルールセット表記(「CoC7e風」等)へ重なる。未ログイン時に確認した「ログイン」と「閉じる」の重なり(375px で 73×4px、`elementFromPoint` で下の要素が occlude される)と同根で、**固定 AuthBar と各画面ヘッダの領域が調停されていない**。

**公開ギャラリー**: 見出し → タブ → 検索 → フィルタ → カード列、と縦の流れは素直で良い。max-width 720px も読み物として妥当。ここは Home より完成度が高い。

### 強調のバランス
- **補助テキストが弱すぎる** — `faint #B8AE93` は紙地に対し **1.78:1**(基準 4.5:1)。しかもこの色が「ログインが必要です」という**最も重要な案内**を担っている。重要度と視覚的重みが逆転している
- **未選択タブが背景に沈む** — 同じく `faint`。選択中タブ(ink 塗り)との差が極端で、「小説/世界観/キャラクター/シナリオ」が選べる項目に見えない
- **境界線が見えない** — `line #C9BFA3` は **1.47:1**(非テキスト基準 3:1)。カード・入力欄の輪郭がほぼ消えており、入力欄が「入力欄に見えない」

## 一貫性

### 最大の問題: 角丸ピルが3つの異なる意味を担っている

公開ギャラリーの「世界観」タブでは、**視覚的にほぼ同一の要素が縦に2列並び、まったく別の挙動をする**。

| 要素 | 実装 | 挙動 | 実測スタイル |
|------|------|------|--------------|
| タブ(おすすめ/小説/世界観…) | `<div>` | 排他選択・**キーボード不可** | `#B8AE93` / radius 3px / 12px / 高さ32 |
| 雰囲気フィルタ(ホラー/冒険…) | `<button aria-pressed>` | 複数選択・**キーボード可** | `#B8AE93` / radius 3px / 12px / 高さ28 |
| カード上の雰囲気ラベル | `<span>` | **非操作**(`cursor: default`) | brassDark / radius 999px |

色・角丸・文字サイズがほぼ同じで、差は高さ 4px のみ。**利用者が「同じ見た目だから同じように動くはず」と学習した直後に裏切られる。** しかも皮肉なことに、キーボードで**使える**方(フィルタ)と**使えない**方(タブ)が見分けられない。

| 要素 | 問題 | 推奨対応 |
|------|------|----------|
| タブ / フィルタ / ラベル | 3つの意味に同一のピル表現 | 形を分ける: タブ=下線付きテキスト、フィルタ=角丸ピル(選択時に塗り)、ラベル=枠線のみ・彩度を落とす |
| カード | `Card` に `onClick` があると `<div>` のまま操作要素になる | `Card` を表示専用に固定し、操作が要るときは `<button>` でラップする API に変更 |
| ボタン | `Button` に `:focus-visible` の定義が無く、`type` も未指定 | primitive 側で両方を既定にする |
| 「公式サンプル」 | 下線付き brass で**リンクに見える**が実体は `<button>` | 見た目をリンクにするなら挙動もリンクに揃える、あるいはボタンとして描く |
| 日付表記 | `2026/7/25` とゼロ埋め無し | 桁揃えするか、`2026-07-25` に統一 |

### モバイルでの文字折り返し

375px 幅で **タブとボタンのラベルが単語途中で改行される**。
- Home: 「+ 新/規プ/レイ」「素材/ライ/ブラ/リ」(4行)「エンデ/ィング/図鑑」
- ギャラリー: 「おす/すめ」「キャラ/クター」「シナ/リオ」「世界/観」

4つの項目を1行に詰め込もうとして各要素が潰れている。**横スクロールさせる、2列グリッドに落とす、または `white-space: nowrap` + 横スクロール**のいずれかを選ぶべき。現状はどの選択肢も取らずに潰れている。

## アクセシビリティ

実測値。詳細と改善計画は [09-accessibility-plan.md](./09-accessibility-plan.md) を参照。

- **コントラスト**:
  - 本文 `ink` on `paper` = **11.68:1** ✅ 良好
  - 入力文字 `inkSoft` on `paper` = **9.53:1** ✅ 良好
  - 補助文/未選択タブ `faint` on `paper` = **1.78:1** ❌ 基準 4.5:1
  - 境界線 `line` on `paper` = **1.47:1** ❌ 基準 3:1
  - brass ボタン文字 `paper` on `brass` = **3.20:1** ❌ 基準 4.5:1(13px は大字扱い不可)
- **ターゲットサイズ**: ボタン 40〜42px ✅ / タブ 32px ✅ / フィルタ 28px ✅ / 「公式サンプル」**18px** ❌ / Toast の閉じる **約18px** ❌(基準 24×24)
- **テキストの可読性**: 本文 14〜16px、和文としては下限に近いが許容範囲。`Source Serif 4` は和文グリフを持たないためフォールバック依存で、和欧混植の字面が不揃いになる箇所がある
- **ランドマーク/見出し**: 実測で `<main>` 0 / `<nav>` 0 / `<h2>` 0。**公開ギャラリーは `<h1>` すら 0**(「公開ギャラリー」は装飾 `<div>`)
- **代替テキスト**: 挿絵はすべて固定文言 `"場面の挿絵"`(場面ごとの情報なし)。アバターは `alt=""` で装飾扱い — 隣に名前があるため妥当

## よくできている点

- **世界観の一貫性** — タイプライター見出し × セリフ体本文 × セピア紙。「AI が GM を務める」という体験に、装飾ではなく必然性のある質感を与えている
- **スターターコンテンツの文章が非常に良い** — 「禁書と魔女裁判の記憶が残る港町。写り込んではならないものが、乾板に写る。」のような1〜2文の導入は、世界観・ジャンル・引きを同時に伝えている。**これは本アプリで最も強い資産**である
- **ログイン後の Home がその資産を正しく使えている** — 「はじめての冒険を選ぶ」という見出し、一式取り込みの説明、カードごとの「この冒険を始める」CTA。初回体験の設計として素直で良い。惜しいのは、この良い版が**ログインするまで一切見えない**こと
- **モーション設計が正しい** — `prefers-reduced-motion` を `theme.js` の単一関数に集約し、ダイス演出・タイプライター・Toast すべてが尊重する。`matchMedia` 非対応環境でも静的表示に倒れる
- **ダイス演出のネタバレ回避** — 「押印前に増減量から大失敗が分かってしまう」ため SAN 増減を押印後に出す(`docs/05-ui-ux.md`)。体験の質に対する解像度が高い
- **生フラグを見せずに「これまでを思い出す」で自然文に翻訳する判断** — 内部状態をそのまま出さない判断は、没入を守る正しい設計
- **公開ギャラリーの縦方向レイアウト** — 見出し→絞り込み→一覧の流れは素直で、max-width 720px も読み物として適切
- **一部コンポーネントの ARIA が適切** — `aria-pressed`、`role="progressbar"`、Toast のライブリージョン(空でもコンテナを描画し続ける実装コメント付き)

## 優先して直すべきこと

### 1. `theme.js` の 3 行を直す — 最小コストで全画面に効く 🔴
`inputStyle` の `outline: 'none'` 撤廃、`COLORS.faint` と `COLORS.line` のコントラスト是正。**単一ファイルの変更で、全画面のフォーカス可視性・補助テキスト可読性・輪郭視認性が同時に改善する。** 最も投資対効果が高い。
世界観との両立が懸念点だが、`faint` は「セピア紙に薄い鉛筆」の印象を保ったまま 4.5:1 まで落とせる余地がある(`#6B6353` 前後)。

### 2. カードとタブを本物のボタンにする 🔴
`Card` の `onClick` API を廃し、操作が必要な箇所は `<button>` でラップする。これで**公開ギャラリー・素材ライブラリの一覧選択がキーボードで操作可能になる**(現在は不能)。タブは `role="tablist"` + 矢印キーへ。
併せて `Button.jsx` に `type="button"` と `:focus-visible` を既定で入れ、**primitive 側に正しさを埋め込む**。個人開発では、都度の注意ではなく既定値で品質を担保するのが唯一続く方法。

### 3. 未ログイン Home をログイン後 Home に近づける 🟡
ログイン後の Home は良くできている。問題は、**その良い版が初回訪問者に見えない**こと。未ログイン時は押せない CTA が主役で、画面の 3/4 が空で、最大の資産である導入文を一切見せていない。
- スターター一覧を**未ログイン時にも表示**する(閲覧は公開ギャラリーで既に可能なので、情報公開上の追加リスクはない)
- 主 CTA を「ログインしてはじめる」にして**押せる状態**にし、そのままログインへ繋ぐ
- ログイン後 Home では、最下部にある主要ナビを上部にも置く(2回目以降の利用者の導線)
- 固定 AuthBar と各画面ヘッダの重なりを解消する(未ログイン時の「ログイン/閉じる」、ログイン後のユーザー名とカード内容)
- モバイルのボタン行を横スクロールか 2 列グリッドに変え、単語途中の改行をなくす

## 今回このブランチで修正した項目

「優先1」に挙げた token 層の修正を実装し、ブラウザ上で実測して確認した。

| 項目 | 変更前 | 変更後 | 変更ファイル |
|------|--------|--------|--------------|
| 補助テキスト `faint` | 1.78:1 | **5.21:1** | `theme.js` |
| 操作部品の輪郭(`lineStrong` 新設) | 1.47:1 | **3.08:1** | `theme.js` |
| brass ボタンの文字 | 3.20:1 | **4.67:1** | `Button.jsx` |
| 入力欄のフォーカス表示 | 変化なし(`outline: none`) | **2px リング + 2px オフセット** | `theme.js`, `styles.css` |
| ボタンの `type` | 全て既定の `submit` | **`type="button"`** | `Button.jsx` ほか計7箇所 |
| Toast 閉じるボタン | 約18px | **24×24px** | `Toast.jsx` |

塗り系ボタン(primary / brass)の上ではリング色を紙色へ反転させるため、`Button` に `data-variant` を付与して `styles.css` から参照している。

**変更したのはすべて共有 primitive と token であり、画面側のコードには触れていない。** テスト 1326 件・ビルドとも通過。

### 続けて実施した構造面の修正(Phase 2 相当)

| 項目 | 変更前 | 変更後 |
|------|--------|--------|
| 一覧カード | `<div onClick>`(キーボード不可) | タイトルを `<button>` 化しオーバーレイで当たり判定を拡張 |
| 作者ボタンの名前 | 全て「公式サンプル」 | 「〈作品名〉の作者 〈名前〉 のページ」 |
| タブ | `<div onClick>` | `role="tablist"` + 矢印/Home/End + roving tabindex |
| モーダル | 素の `<div>` 重ね | `role="dialog"` + `aria-modal` + フォーカストラップ + Esc + 復帰 |
| フォームのラベル | `<div>`(関連付けなし) | `<label htmlFor>` / 群は `role="group"` + `aria-labelledby` |
| 未ログイン案内 | カードごとに7回 | 一覧の先頭に1回 |
| ログイン↔閉じる の重なり | 375px で 73×4px | **0**(帯を確保) |
| モバイルのラベル折り返し | 「おす/すめ」「素材ラ/イブラ/リ」 | `nowrap` + 行送りで語中改行を解消 |
| 固定 AuthBar の透け | 本文と重なって判読不能 | 紙色の背景を敷いて分離 |
