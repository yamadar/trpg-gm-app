# 公開一覧の検索・絞り込み・ページネーション 設計書

作成日: 2026-07-24

## 背景

Phase 1(認証)・Phase 2(共有)・Phase 3(ユーザーページ)完了後のフォローアップ。公開ギャラリーとユーザーページの一覧が全件表示のままなので、検索・絞り込み・ページ送りを入れて素材を見つけやすくする。

現状の `listPublic` は公開メタを毎回全件読み込んでソートしている(ユーザーページは4種別ぶん全走査)。

## 確定した要件

- **規模前提**: 当面は数十〜数百件。**索引は作らない**(サーバーで全件読み→絞り込み→ソート→スライス)。APIの形だけ将来索引を入れても変えずに済むよう決めておく
- **テキスト検索**: `title` / `ownerName` / `worldTitle` の部分一致(大文字小文字無視)
- **絞り込み(ファセット)**: 雰囲気(複数選択・OR)、推奨ルールセット(シナリオのみ)
- **雰囲気タグ**: 固定語彙・複数選択。**素材本体**に保存(再公開で引き継がれ、将来ライブラリ側でも使える)。対象は**世界観とシナリオ**
- **世界観での絞り込み**: 専用プルダウンは作らず、テキスト検索が `worldTitle` を含むことで賄う(動的な選択肢APIを避けるため)
- **適用画面**: 公開ギャラリー + ユーザーページ(素材ライブラリ=非公開側は対象外)
- **ページ送り**: 「もっと見る」ボタン(追記型)

## アプローチ選定

**案A: サーバー側でクエリ処理**を採用。一覧APIがクエリパラメータを受け、絞り込み・ソート・スライスして返す。

比較した代替案 — **案B: クライアントで全件保持して絞り込み**は実装が簡単で絞り込みが瞬時だが、公開物が増えるほど初回転送が重くなり、将来索引を導入しても全件送る限り無意味で、ページネーション導入の動機と噛み合わない。

採用理由: 転送量が一定に保たれ、将来アイテムが増えて索引を導入する際も**APIの形を変えずに内部実装だけ差し替えられる**。ユーザーページも同じAPIに `ownerId` を付けるだけで賄える。

## 1. 雰囲気タグ(新規フィールド)

### 語彙

固定8種: `ホラー` / `冒険` / `ミステリー` / `日常` / `SF` / `ファンタジー` / `コメディ` / `シリアス`(後から追加可能)

- サーバー: `server/storage/moods.js` に `MOODS` をexportし、保存時に語彙外を拒否
- クライアント: `src/constants/moods.js` に同一の配列(選択UI用)
- 両者は同内容の二重定義。既存の `server/storage/slugify.js` ↔ `src/utils/slugify.js` と同じ前例に倣い、互いを指すコメントを入れる

### 保存場所

素材本体のメタに `moods: string[]` を追加:

- World: `{ id, title, updatedAt }` → `+ moods`
- Scenario: `{ id, worldId, title, recommendedRuleset, updatedAt }` → `+ moods`

既存素材は `moods` 不在 → 読み出し時 `?? []` で補完(マイグレーション不要。Phase 3の `bio ?? ''` と同じ手口)。

### 入力UI

素材ライブラリの World / Scenario タブに複数選択(チップ)を追加。保存は既存の PUT に `moods` を含める。サーバーは配列であること・全要素が語彙内であることを検証し、違反は400。

## 2. 公開メタへの反映

公開(スナップショット)時に絞り込み用の情報を公開メタへ載せる:

- worlds: `+ moods`
- scenarios: `+ moods`, `+ worldId`, `+ worldTitle`
- characters: `+ worldId`, `+ worldTitle`

`worldTitle` は公開時に所有者の世界観メタから読む(取得できなければ `null`)。

**既に公開済みのアイテムにはこれらが入っていない。** Phase 2で確定した「再公開でスナップショットを更新する」意味論どおり、再公開すれば付与される。自動バックフィルは行わない。付与前は該当の絞り込みにヒットしないだけで、一覧表示・詳細・インポートは従来どおり動く(欠損は `?? []` / `?? null` で吸収)。

## 3. 一覧API

### 形

```
GET /api/public/:type?q=&moods=ホラー,冒険&ruleset=coc7e&ownerId=usr_x&limit=20&offset=0
→ 200 { items: [...], total: number, hasMore: boolean }
```

- `q`: `title` / `ownerName` / `worldTitle` の部分一致、大文字小文字無視。空文字は未指定扱い
- `moods`: カンマ区切り。**いずれか1つでも合致すればヒット(OR)**。語彙外の値が混ざっていても400にはせず無視する(読み取り系を壊さない)
- `ruleset`: `recommendedRuleset` と完全一致。シナリオ以外の種別では実質ヒットしない
- `ownerId`: 指定ユーザーの公開物だけに絞る(ユーザーページ用)
- `limit`: 既定20、上限100(超過は100に丸める)、`offset`: 既定0。負値・非数は既定値に丸める
- 並びは従来どおり `publishedAt` 降順。絞り込み後の件数が `total`、`offset + items.length < total` が `hasMore`
- `offset` が `total` 以上なら `items: []`(エラーにしない)

### 破壊的変更と統合

- 従来 `GET /api/public/:type` は**配列を直接**返していた。`{ items, total, hasMore }` に変更する。利用箇所(`shareClient.listPublic` / Gallery / UserPage / 各テスト)を併せて更新する
- **`GET /api/users/:userId/public` は廃止**し、`GET /api/public/:type?ownerId=...` に統合する(唯一の利用者がユーザーページのため)。プロフィール取得の `GET /api/users/:userId` は変更しない
- 認証は従来どおり不要(公開読み取りルーターのまま)

## 4. UI

一覧部分を共有コンポーネント **`src/components/share/PublicItemList.jsx`** に切り出し、Gallery と UserPage の両方から使う(Phase 3で詳細を `PublicItemDetail` に切り出したのと同じ流儀)。

`PublicItemList({ type, ownerId, onOpenDetail, onAuthorClick })`:

- 検索窓: 入力から **300ms デバウンス**して再取得
- 雰囲気チップ(複数選択): **worlds / scenarios タブでのみ表示**
- 推奨ルールのプルダウン: **scenarios タブでのみ表示**(選択肢は既定ルールセット `simple` / `coc7e` / `dnd5e` / `gurps`)
- 一覧カードは現行の見た目を踏襲(タイトル / 作者名リンク / 公開日、キャラは種別バッジ)
- 下部に「もっと見る」(`hasMore` が真のときだけ表示)。押すと次の `limit` 件を**追記**
- タブ・検索語・絞り込みのいずれかが変わったら `offset` を0に戻して先頭から取り直す
- 0件時: 絞り込みなしなら「まだ公開されたものがありません」、絞り込み中なら「条件に合う公開物がありません」+「条件をクリア」ボタン
- 取得中・取得失敗の表示。stale-response ガード(直近リクエストの結果だけ反映)を入れる

Gallery / UserPage は一覧の状態管理をこのコンポーネントに委ね、詳細表示(`PublicItemDetail`)への切替のみ担う。

## 5. エラーハンドリング

- 不正な `limit`/`offset`(非数・負値・上限超過)は400にせず既定値/上限に丸める(読み取り系を壊さない)
- 語彙外 `moods` はクエリでは無視、**保存時のみ**400
- `worldTitle` が取れない公開物は `null` のまま。`q` の照合対象からは自然に外れる
- クライアントは既存 `apiFetch` の 401/429 ハンドリングをそのまま利用

## 6. テスト戦略

- **サーバー(一覧API)**: `q` / `moods` / `ruleset` / `ownerId` それぞれ単独と組み合わせ、`total` と `hasMore` の正しさ、`limit` 上限丸めと `offset` 超過で空配列、`moods` のOR挙動、語彙外moodがクエリでは無視されること、`ownerId` で他人の公開物が混ざらないこと、**メタに `moods`/`worldTitle` を持たない旧公開物が素通しされ落ちないこと**
- **ストレージ**: `saveWorld`/`saveScenario` の `moods` 往復と `?? []` 補完、語彙外の保存が拒否されること、公開スナップショットに `moods`/`worldId`/`worldTitle` が載ること
- **クライアント**: `PublicItemList` の検索デバウンス、絞り込み変更で先頭に戻ること、「もっと見る」の追記、0件表示の出し分け、Gallery/UserPage が同部品で従来どおり動くこと(詳細表示・インポートは不変)、ライブラリタブの雰囲気選択UI

## スコープ外

- 索引の導入(将来、APIの形を変えずに内部だけ差し替える)
- 本文(Markdown)の全文検索
- 自由入力タグ
- 並び替えの選択(常に `publishedAt` 降順)
- 素材ライブラリ(非公開)側の検索・ページネーション
- 既存公開物への自動バックフィル(再公開で付与)
- キャラクター・小説への雰囲気タグ
